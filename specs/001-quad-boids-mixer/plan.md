# Implementation Plan: Quadraphonic Boids Mixer

**Branch**: `001-quad-boids-mixer` | **Date**: 2026-05-10 | **Spec**: [spec.md](spec.md)

---

## Summary

A quadraphonic audio firmware for the Electrosmith Daisy Patch (STM32H750, Cortex-M7 @ 480 MHz). Four mono audio inputs are panned across four outputs (FL, FR, RL, RR) using an equal-power bilinear pan law. Audio Inputs 1 and 2 are positioned in real time via CV1–CV4 (X/Y axes). Audio Inputs 3 and 4 each follow one of three independently-selectable path types — circular, figure-8, or boids — with path and rate selected via the encoder. The boids mode runs two independent flocks of 32 virtual agents each in the main loop at 100 Hz; flock centroids drive spatial positions written to shared `volatile float` state and consumed by the audio callback. All DSP runs heap-free in the audio callback. The boids simulation, OLED rendering, and UI logic run in the main loop.

## Architecture Overview

### Audio Callback (interrupt context, every 32 samples @ 48 kHz)

```
ProcessAnalogControls()          → refresh CV ADC
ProcessDigitalControls()         → refresh encoder state
g_enc_delta += encoder.Increment()
if (encoder.RisingEdge()) g_enc_pressed = true

for each input 1..4:
  target_x = (input is CV) ? map(cv_x) : g_auto_pos_x[i]
  target_y = (input is CV) ? map(cv_y) : g_auto_pos_y[i]
  smoothed_x = IIR(smoothed_x, target_x)
  smoothed_y = IIR(smoothed_y, target_y)
  gains = PanLaw(smoothed_x, smoothed_y)

for each sample in block:
  out[FL][n] = Σ (in[i][n] × gains[i].fl) × 0.5f   // 0.5f = −6 dB headroom
  out[FR][n] = Σ (in[i][n] × gains[i].fr) × 0.5f
  out[RL][n] = Σ (in[i][n] × gains[i].rl) × 0.5f
  out[RR][n] = Σ (in[i][n] × gains[i].rr) × 0.5f
```

### Main Loop (non-interrupt, runs continuously)

```
while (1):
  dt = elapsed since last tick

  // UI (~every call, cheap):
  enc = g_enc_delta; g_enc_delta = 0
  if (g_enc_pressed): g_enc_pressed = false; cycle_path(selected_input)
  handle_enc_rotation(enc, selected_input)

  // Path update (~100 Hz, throttled):
  if (dt_since_path_update >= 10ms):
    path3.Update(dt)
    path4.Update(dt)    // runs boids if active
    g_auto_pos_x[0] = path3.GetPosition().x
    g_auto_pos_y[0] = path3.GetPosition().y
    g_auto_pos_x[1] = path4.GetPosition().x
    g_auto_pos_y[1] = path4.GetPosition().y

  // Display (~20 fps, throttled):
  if (dt_since_display_update >= 50ms):
    RenderDisplay()     // clear, draw field, draw markers, draw status bar, Update()
```

## Key Implementation Notes

1. **Encoder ghosting**: `encoder.Increment()` MUST be accumulated inside `AudioCallback` only. Reading it in the main loop produces erratic multi-fire. See research.md §3.

2. **DrawLine coordinate clamping**: Every `patch.display.DrawLine(...)` call MUST have its arguments clamped to [0,127] × [0,63] before calling. Negative values wrap to ~4 billion and hard-freeze the firmware. See research.md §3.

3. **Boids update rate**: Update boids at 100 Hz (every 10 ms), not every main-loop iteration, to control CPU load. Use a `System::GetNow()` timestamp comparison for throttling.

4. **Profiling gate**: After the boids implementation is complete and before any path or display work begins, measure the boids update time with a GPIO toggle and oscilloscope. If > 5 ms (50% of 10 ms budget), reduce N_BOIDS from 32 to 20 and re-profile.

5. **Smoothing cutoff**: Use a one-pole IIR coefficient for ~10 Hz cutoff at 48 kHz: `alpha ≈ 1 - exp(-2π × 10 / 48000) ≈ 0.00131`. This gives a ~100 ms position lag — slow enough to eliminate zipper noise, fast enough for expressive CV control.

6. **Zero-warning policy**: Build with `-Wall -Wextra`. Fix all warnings before any commit. clang-format must be run on all changed `.cpp`/`.h` files.
